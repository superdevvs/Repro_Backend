# Staging layout recipe v3 diagnostic candidate

The real medium/12k diagnostic returned a completed request for native details, but two optional source polygons were concave. Recipe v3 retains medium/12k and all schema, compiler, source views and strict parsing. Its only behavior change is a prompt instruction: held/adaptive decisions return `layout:null`; a draft requires complete valid geometry and every existing source, scale, clearance and optics gate.

The parser already supports null adaptive geometry. Its bounded prior-result contract still binds the full source gate and exact requested native-detail/reframe operation. Null draft geometry remains ineligible, malformed populated geometry still rejects, and one source follow-up remains the limit. No geometry is normalized or repaired by this change.

Recipes v1/v2 and retained responses remain immutable. This candidate registers v3 but does not select it for normal workflows, change the four-analysis budget, add an automatic paid retry or alter production configuration. A standalone exact-source pilot is diagnostic only and cannot be inserted into an existing workflow or grant image authority.
