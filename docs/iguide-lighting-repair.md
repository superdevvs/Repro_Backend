# Bounded lighting repair

This opt-in workflow extension is disabled by default (`IGUIDE_LAB_LIGHTING_REPAIR_ENABLED=false`). It does not change the image model, credential fallback rule, original source, or existing analysis recipe identity. Enabling it requires a newly validated runtime manifest containing the exact `validatedGlobalLightingSha256`, worker, geometry, source adapter and preparer hashes. A release must drain existing workflows before changing these shared worker files.

An independent quality result may authorize a free global color candidate when optical consistency fails, geometry/seam/poles/protected features pass, and the recommended action permits repair. Uncertain optics and manual-review recommendations do not authorize this route. The quality record, raw response, provider identity, exact request payload and seven paired evidence images are revalidated before reuse.

The new composition uses the latest confirmed original-source image run as color guidance. It derives one robust three-channel linear-RGB log-odds offset, then applies the existing bounded source-native transform and fixed nadir policy. It copies no generated spatial detail. It cannot recreate directional illumination, lamp emission, hidden surfaces, reflection geometry or cross-camera consistency. Equal source colors remain equal outside the fixed nadir fade, but that is not proof of correct optics or sufficient preset effect.

Each distinct image run may receive at most one global candidate; an item may receive at most two. Normal and global composites have separate immutable step IDs and independent evaluation records. The overall ceilings are three paid image records, two scene analyses, five compositions and five evaluations. Explicit quota fallback remains a separately recorded transport attempt under the existing credential policy, not a new semantic repair. A submitting or ambiguous child is never blindly retried.

A failed local candidate does not become ready merely because it preserves geometry. The independent checker still evaluates the original intent, including visible preset effect. When a replan/regeneration is justified and the analysis/image budgets remain, a new private repair-analysis recipe sees all seven **source-left / failed-candidate-right** native-derived boards and the complete bounded structured check feedback. No reasons or dependencies are shortened. The source halves alone are geometry authority. The returned image-facing prompt describes the source edit, not the internal review process. If a complete supported repair context cannot be constructed, the item remains `needs_review`.

Full repair context and raw receipts stay private. Public analysis DTOs retain their existing shape with empty diagnostic views, `sourceContext: null`, and explicit new view/compiler/instruction version strings. Image provenance continues to bind the actual analysis ID, source and proposal; the private analysis record retains the full repair association. Composite lineage records the retained run, failed candidate/evaluation, global recipe, numerical telemetry and zero new paid image calls.

Validation includes pure transform invariants, actual receipt tamper checks, full-feedback and seven-board binding, per-image/total budgets, failed-intent handling, and recovery after a composite attachment but before its item checkpoint. `tests/Integration/lighting_repair_workflow.php` exercises imported original → analysis → image → ordinary composition → failed check → global composition → check → optional full-context replan, using actual pinned image workers and intercepted fake HTTP only. Synthetic evaluator passes demonstrate mechanics, never real scene quality or manual acceptance.
