# Listing Studio paid orders

Paid ordering is disabled by default. Enablement requires separate review of `listing-studio.paid_enabled`, `paid_checkout_enabled`, `paid_services.*` and `human_revisions_enabled`. Existing free trials and staff requests retain their authorization rules; new paid client routes keep the existing email-verification policy and reject impersonated billing.

The dashboard catalog is canonical for current plans, services and staging options. The website bridge can read `/api/external/listing-studio/catalog` using its existing scoped credential and session. It has no paid ordering or account authority. Historical request codes remain unchanged and are returned as `historical_plans`/`historical_services` for history labels only; exact historical request replay is preserved.

Quotes snapshot server prices, discounts, source identity and supported options. A quote expires by 15 minutes, the relevant paid period boundary or source expiry, whichever comes first. An accepted order uses either dollar-denominated editing credit or a card payment, never a mixture. Exact request replay returns the same order before checking new-admission gates or limits.

Credit reservations reduce available credit atomically, capture once after private delivery is validated, and release only after a definitive failure or cancellation. The reservation remains tied to the original paid period through recovery and renewal. It does not become credit in the next period. Existing paid-invoice/proration/refund synchronization remains authoritative for grants and adjustments.

Verified Stripe events with a complete canonical refund snapshot fund card orders; browser return URLs and canonical session reads never settle purchases. Economic deduplication uses the payment intent under the persisted Stripe account/mode. Refund amounts increase only on canonical succeeded refunds. Existing pending or succeeded refunds prevent a late checkout event from starting an edit. Failed/cancelled refund records cannot regress to pending, and financial events preserve already-started fulfillment state. Repeated payment events cannot reopen an existing completed refund operation. Refund state and fulfillment state are separate.

Financial transitions and durable dispatch intents share short `LockedWrite` transactions. Provider, queue, Stripe and filesystem operations run outside them. The minute scheduler invokes `listing-studio:orders-dispatch --limit=100`; uncertain dispatch retries preserve event identity and payload. Five-minute dispatcher leases use conditional lease-token completion so stale workers cannot finish a replacement lease. Unknown event types are held for review.

By default, a client may retain 20 active upload sources and 20 awaiting-payment card orders. Inputs pinned by awaiting-payment orders count toward the source limit, including expired pinned inputs. New order allocation is serialized; funded and finished history is excluded. An owner can cancel an unpaid awaiting-funding card order only when no checkout attempt exists or all attempts are definitively failed/expired. Checkout allocation rechecks that same state under its transaction. Ambiguous, open and awaiting-webhook checkouts cannot be cancelled through this action.

Account and transaction history are owner-scoped. Current-period reserved credit is distinct from spendable credit; historical reservations remain visible on their orders. Transaction entries are signed cents without invented balance snapshots. Existing eligible billing customers can open billing management even while new purchases are disabled. Private paths, payment credentials and provider payloads never enter customer DTOs.

Focused validation lives in `ListingStudioFinancialCoreTest`, `ListingStudioOutboxTest`, `ListingStudioRequestTest`, the Stripe adapter/integration tests and paid processing tests. The core test races independent file-backed SQLite processes against the last spendable balance and last unpaid-order slot; outbox tests cover response loss, same-identity retry and stale lease completion. All provider/payment boundaries are faked during these tests; no live payment or generation is required.
