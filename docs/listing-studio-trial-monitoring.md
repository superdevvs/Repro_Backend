# Listing Studio trial monitoring

Run `php artisan listing-studio:trial-health` for a read-only JSON snapshot. It does not reconcile jobs, read images, contact providers, change flags, or send alerts. Exit 0 means no configured health threshold was reached; exit 1 means the `warnings` array is nonempty. No new scheduler or external notification is installed.

The report contains:

- Starts, current statuses, durable pipeline completions, and queue-delay p95 by service for trials started in the last 24 hours. A completion remains counted after unclaimed media expires; it is not a visual quality score. Queue-delay samples use the first persisted `worker_started_at`; older trials without this field are not inferred or backfilled.
- All current queued, processing, and `needs_attention` records; warnings for queued over five minutes, processing over fifteen minutes, and completed workspaces whose trial is still queued, processing, or needs attention. These are operational thresholds, not automatic retry instructions. No provider resubmission is performed.
- Exact rolling 24-hour start usage against global and per-connection limits, including failed attempts and QA. The report returns only aggregate connection counts, never IP hashes or addresses.
- Claimed clients/trials and download requests for the same start cohort. `first_download_requested_at` and `download_request_count` record authorized ready-file response requests, not completed browser transfers. Requests before this instrumentation was deployed are not backfilled. The new-account numbers compare account creation time with the cohort's earliest trial start; they are an attribution proxy, not proof that the trial caused signup.
- Fixed-vocabulary event counts for the current and previous UTC calendar days. These daily buckets are **not** exact rolling 24-hour request counts. Exact replays, changed-payload idempotency conflicts, active/service allowances, global/IP/admission/rate limits, and selected admission/challenge failures are counted after the outcome transaction ends. No session, token, IP, user, file path, prompt, or request payload is stored in the counter table.

Only the seven frozen provider-QA trial UUIDs in `config/listing-studio-trials.php` → `monitoring_qa_trial_ids` are excluded from conversion reporting. Their usage, failures, stuck jobs, and finalization gaps remain included in health and quota reports. The subsequent real website upload is not excluded. Changing this list does not change enforcement or entitlements.

Telemetry writes are best-effort and cannot replace the job, admission, claim, or download outcome. Production SQLite writes use a separate PDO connection to the verified existing primary database file, opened with `mode=rw` and a 100 ms lock timeout. Each observation is one atomic statement, with no ordinary business-write retries or raw SQL exception logging; the primary timeout is untouched. An anonymous in-memory test database uses its original PDO with the timeout restored in `finally`. Unsupported drivers/files are skipped with a generic error. Database failure produces no request fields; missing observations remain possible. The existing hourly `listing-studio:prune-guest-trials` task keeps at most 90 UTC days of aggregate buckets. It retains trial entitlement/history rows. The health command itself never prunes.

Existing authenticated System Overview traces remain separate and retain 24 hours. They omit anonymous bridge/admission requests and identify the download route/user rather than a durable per-trial transfer. The trial report fills those operational gaps without enabling generic anonymous request telemetry.

Owner paths: `ListingStudioTrialMonitoring` computes aggregates and persists observations; `ProcessStudioWorkspace` records the first worker start; `ListingStudioGuestTrialService` and `ListingStudioTrialAdmission` report allowlisted business outcomes; `ListingStudioGuestTrialController::download` records successful authorized download requests. This is phase-one operational monitoring; there is no billing or analytics UI change.
