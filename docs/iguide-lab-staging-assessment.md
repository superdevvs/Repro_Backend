# Internal staging placement assessment candidate

This is an internal durable child record, separate from scene planning and final visual quality evaluation. It is not enabled in the public workflow policy, has no public HTTP route, and does not bind the machine segmentation authority interface by default. Existing lighting workflows retain their two-analysis budget and existing request identity.

The explicit `empty-living-three-piece-staging/1` policy reserves three analysis steps (source routing, actual-section draft, actual-candidate placement), one image, two ordered segmentation steps and one final evaluation. Its supported arrangement is one sofa, one chair and one coffee table in an otherwise supported empty living space. Missing coverage, unresolved optics, uncertain object identity or unsupported floor/foreground conditions produce `needs_review`; schema validity is not quality acceptance.

`LabStagingAssessments::reserve(item, sectionId, candidateRunId)` loads the immutable same-project native source and actual completed section and image. It requires machine child reservations and a completed source-bound section proposal. The authoritative final output digest is checked against actual bytes. The original extraction manifest binds source, cut, dimensions and pose. Evidence is ordered: source cut, candidate cut, original parent overview and four original parent cardinals. Parent views are generated from the server's actual GD-prepared native source with the existing pinned diagnostic worker; client paths or successful-review assertions are never authority.

The assessment context uses a five-field pose including image dimensions. The separately stored support geometry uses only `yaw`, `pitch` and `hFov`, with top-level width and height. Their distinct exact hashes are retained. The normalized geometry descriptor also retains the original extraction manifest digest.

`start(step)` persists a typed assessment with the stable step request UUID, exact input hash, implementation snapshot and exact compiled payload before dispatch. Replay repairs a missing child attachment and reconciles scheduling only for an untouched queued record, after fresh source and cancellation checks. Submitting, received and unknown states are never submitted again by replay. The private Python bridge recompiles ordered embedded inputs when parsing a received response and validates context, execution and payload hashes. Only its compact structured result is consumed; hidden model reasoning is not exported.

States are `queued`, `submitting`, `received`, `completed` and `needs_attention`. Each paid attempt has an atomic project/cancellation claim before HTTP. Only an explicit exhausted-quota response permits the configured fallback, using identical saved payload bytes. Unknown outcomes never retry. A durable known receipt enters `received`; parsing runs on a later bounded job tick without another provider request. Submission allows at most 360 seconds of total provider time plus two 90-second local preflights within a 600-second job. Receipt parsing is a separate bounded phase. Queue retries cannot resubmit a `submitting` record with no known receipt.

`reserveSegmentationSteps(record)` persists both child UUIDs without submitting either. `forSegmentation(step)` revalidates the completed typed assessment, actual source/candidate/context and result asset, binds the saved UUIDs through the pure protocol, and returns the complete bound plan plus assessment identity. `associate(step, receipt)` performs that same trusted lookup again before pure receipt association. The separate SAM executor remains responsible for requiring a successful hash-exact original-floor receipt before a candidate-furniture claim. No concrete authority binding is installed by this candidate.

The runtime is separate and unavailable by default: `/home/maverick/iguide-ai-runtime-staging-assessment-v1/runtime-manifest.json`. Readiness requires a passed manifest binding the current PHP context/bridge, pure protocol, Python bridge, source preparer and diagnostic geometry hashes, with Python 3.12.3 and Pillow 13.0.0. The bridge has a 1 GiB address-space and 30-second CPU bound; ordered image evidence is limited to 24 MiB. Files are private, immutable and checked on replay.

Validation includes durable replay and known-receipt resume, quota fallback identity, cancellation before fallback, ambiguous no-retry behavior, source/result drift, unchanged lighting budget and foreign output rejection. Separate pinned Linux proof covers the actual bridge CLI and native-import → actual extraction → parent diagnostic preparation → context compilation with no providers. Synthetic records establish mechanics, not real staging quality.

Before a staging route can become ready, integration must also provide the imported-native-aware section analysis origin/version and exact parent context, the reviewed SAM authority bridge and validated support worker, and actual end-to-end fake-provider tests. The existing uploaded-native-attachment origin must never be asserted for an imported native source. This candidate does not claim unattended staging support or change any accepted artifact.
