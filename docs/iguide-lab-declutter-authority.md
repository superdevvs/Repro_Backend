# Isolated automatic declutter candidate

This candidate adds a bounded source-removal workflow behind `IGUIDE_LAB_DECLUTTER_WORKFLOW_ENABLED=false`. It registers no new public write route or caller-supplied authority. Existing recipe snapshots and dispatch behavior remain unchanged when the flag is false. Separate validated removal-plan and support runtime manifests are required before readiness can be advertised.

## Supported proposal scope

One compact, opaque, clearly decorative tabletop object on a simple continuous matte receiver. The complete object and any attributable short local shadow must fit inside a 10% source-cut margin. The plan explicitly describes hidden receiver pixels as a generated estimate, never recovered ground truth.

Transparent objects, reflective or patterned receivers, multiple or functional objects, thin foliage or open silhouettes, shared/long shadows, uncertain foreground ordering and off-cut optical dependencies hold for review. Unresolved original source-plan caveats also hold; the second proposal cannot silently discard them.

## Source authority and inputs

`LabDeclutterRemovalContext` loads an actual workflow-owned completed source analysis and section. It verifies the native source through `LabWorkflowSources`, the exact native/cut/extraction receipt and pose, and the imported-native or server-owned attachment context through `LabAnalysisSourceContext`. A client metadata assertion cannot substitute for a completed creating import. Unknown room metadata is not inferred.

The typed protocol receives exactly six labelled images: the immutable source cut, its original parent overview and front/right/back/left projections. All are views of one capture, not additional calibrated cameras. Original source-plan constraints are retained in full within a bounded context; oversized input holds instead of being truncated. The exact actual cut hash and separately prepared future image-input hash remain distinct.

## Durable execution

The `removal-plan` workflow step owns the sole request UUID. A separate `IguideLabDeclutterRemovalPlan` record stores the exact context, compiled payload, model response, provider attempt and parsed result. It is not a successful ordinary `IguideLabAnalysis` and must never be represented as one.

Only a never-submitted queued record may be dispatched on reservation replay. An ambiguous submission holds. A known durable receipt can be parsed without another provider call after fresh source and cancellation checks. Fallback is permitted only after an explicit primary quota rejection, using the same payload. Completed authority rehashes its own response file, payload and execution record, verifies provider identity and attempt history, and compares parsed JSON canonically while retaining its exact-byte hash.

The plan yields `target_object` and, only when positively declared, `target_local_shadow`. Both SAM inputs are the exact original 2048-square cut. Each role permits one box, one mask and at most one POST. Persisted workflow-step UUIDs are injected into the otherwise unreserved logical plans. Shadow execution requires a current verified object receipt. Mask return order is not identity, empty masks hold, and machine selection never carries a human-review claim.

## Bounded workflow and native artifact

The machine driver reserves at most one source routing analysis, one typed source-removal plan, one source-only object SAM, one optional local-shadow SAM, one image, one composition and one independent evaluation. Unknown or unsupported source routing holds before further paid steps. The actual native-derived cut is used for the typed plan, SAM and image; imported native sources are verified through their completed creating import rather than forged attachment metadata.

Source support is built before image generation. Binary source masks must have a compact connected solid object, no unresolved holes, no protected-feature conflict and a complete 10% frame margin. Any declared shadow must be local and touch a small neighborhood of the object. A fixed four-pixel expansion and inward two-pixel feather are bounded to 131,072 positive pixels. The original object/shadow union stays opaque. No candidate-derived mask or human-reviewed mask record is created.

The internal image transport uses the exact typed generation prompt, source-only high/low Sunburst settings, and a persisted `sourceMachinePlan` snapshot. It explicitly does not claim `sourceAnalysis`. Public controllers cannot supply the typed fourth service argument or select `machine-removal-plan`. Queue replay revalidates the typed receipt, exact source preparation, support, workflow invocation and cancellation before any submission.

The immutable generated candidate is corrected with the existing exact-domain harmonic solver, then reprojected once in replacement mode through the source support onto the original native panorama. The existing clipping/overshoot limits remain unchanged. Candidate changes elsewhere in the square photograph do not enter the native artifact. The native effective alpha and numerical outside-support checks are retained, along with the exact extraction pose, raw donor lineage, harmonic report and machine receipt hashes.

Seven source/candidate full-sphere boards feed the existing independent visual evaluator. The context includes fixed removal intent, exact selected target, complete original source protections and the explicit unobserved hidden-surface limitation. The original user intent is not replaced with model instructions. A pass means only `passed_automated_checks`; it is neither manual acceptance nor cross-view verification. No second image or automatic repair is permitted.

## Read contract and activation

The run DTO may contain `options.promptMode=machine-removal-plan` and `options.sourceMachinePlan`, including separate native-source, actual-cut and prepared-input hashes, the server-owned parent-context binding, removal-plan/result/support hashes and `humanReviewed=false`. The existing `sourceAnalysis` field is absent. Frontend strict readers must validate this additive read shape before activation; the public write contract remains unchanged. Workflow artifact metadata retains the actual extraction pose for later viewer focus, without asserting camera calibration.

Private full-chain fixtures intercept every provider request and use disposable imported sources. Runtime validation manifests and explicit deployment enablement remain separate from source code. No real provider call or production readiness is established by this document.

Tests use synthetic evidence and intercepted HTTP. Passing authority or receipt tests establishes no real-scene removal quality or unattended end-to-end success.
