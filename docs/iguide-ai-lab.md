# Private iGUIDE AI lab

This URL-only experiment uses a separate expiring capability, never the public Listing Studio guest-trial authority. It preserves original tours and produces 2048-pixel previews. The lab does not publish to iGUIDE or claim cross-view consistency or native-resolution restoration.

Create an operator-authorized project with `php artisan iguide-lab:create "RePro iGUIDE Lab" --days=30 --max-runs=60 --token-file=/private/new-file`. The command saves a 0600 capability file and prints only the project ID. Keep the token server-side in the website's scoped session proxy. Every API request requires `Authorization: Bearer <capability>`; it cannot access Dashboard accounts or billing. Revoking a project's `revoked_at` or reaching its expiry disables access and queued work.

All JSON responses use `{ "data": ... }`:

- `GET /api/iguide-lab`: project allowance, exact configured models, presets, styles, source cases and runs.
- `POST /api/iguide-lab/cases`: multipart `image`, `label`, `projection` (`equirectangular` or `rectilinear`), optional `roomId`, `panoId`, `tourUrl` and JSON-string `metadata`. No remote image URL is fetched. Exact 2:1 is required for panoramas. Uploads allow 30 MB and 64 MP; submitted derivatives are downscaled to at most 2048 pixels. Uploaded width/height/hash describe the upload; original scan resolution and hash belong separately in metadata.
- `POST /api/iguide-lab/runs`: `caseId`, exact `modelId`, `preset`, UUID `requestId`, optional `style`, `prompt`, `options`. Options: `roomType`, `furnitureDensity` (light/balanced/full), `lightingIntensity` (natural/dramatic), `preserveArchitecture`, `preserveFixedFinishes`, `allowFinishChanges` (interior-design only), `referenceCaseIds`, `referenceRunIds`. References must belong to the project; generated references must be completed, and at most three combined references are allowed. Target image is first. An identical requestId replays its existing run; changed settings return 409.
- `GET /api/iguide-lab/runs/{id}`: immutable requested model/settings, status, provider request ID, actual output dimensions, usage when supplied, elapsed processing milliseconds, error, and authenticated output path. Status is `queued`, `submitting`, `processing`, `completed`, `failed`, or `needs_attention`.
- `POST /api/iguide-lab/runs/{id}/reviews`: append-only operator QA for completed outputs. Body: UUID `requestId`, `verdict` (`accepted` or `needs_work`), `checks` containing `edit`, `geometry`, `seam`, `appearance`, `crossView` (each `pass`, `fail`, `unreviewed`, `not_applicable`), optional `notes` (4000 characters), required `pipeline` (`whole_panorama` or `perspective_sections`) and `scope` (`single_panorama` or `cross_view`), optional `batchId` (100 characters) and `metrics` (JSON object, 8 KB). Accepted requires the first four checks to pass; cross-view scope additionally requires crossView pass, while single-panorama scope requires crossView not_applicable. New review returns 201; identical requestId replays with 200, changed content returns 409. Run DTOs expose nullable `latestReview`; older reviews remain stored. Reviews report operator judgments, not a guarantee of perfect geometry.
- `GET /api/iguide-lab/assets/case/{id}` and `/assets/run/{id}`: capability-scoped private images with no-store and noindex headers.

The allowed OpenAI models are `gpt-image-2.6-sunburst`, `gpt-image-2.6-flare`, `gpt-image-2.5-sunburst` and `gpt-image-2.5-flare`; they use Images edits, high quality, one PNG, no input_fidelity. The exact 2.6 models support low/medium/high complexity (medium default). The 2.5 models reject that field; their stored options and multipart requests omit it entirely, preserving the provider default. Seedream is exactly `bytedance/seedream/v5/pro/edit`, standard prompt enhancement, one PNG. All equi outputs request 2048×1024. Prepared input PNG hashes are persisted before provider submission. Response dimensions are checked; unexpected dimensions are not stretched.

OpenAI lab calls require the worker-owned primary credential at `storage/app/private/iguide-lab-credentials/openai-primary.key` (file 0600, worker owner, directory 0710 with www-data group). Deploy configuration caches only its path, never the secret. Missing, empty or unreadable primary credentials fail closed. Only an explicit HTTP 429 quota rejection (`insufficient_quota`, `credit_balance_exhausted`, `organization_usage_limit_exceeded`, `organization_spend_limit_exceeded`, `project_spend_limit_exceeded`, or legacy absent code with type insufficient_quota) allows one attempt using the existing Dashboard OpenAI key. Generic rate limits, authentication failures, unknown errors and ambiguous transport failures never switch credentials. Identical credentials do not cause a second attempt. Global Studio configuration is untouched. See the provider's [documented error codes](https://developers.openai.com/api/docs/guides/error-codes).

`options.providerAttempts` records safe credential-source labels, exact requested models, HTTP status, request IDs, durations and outcomes without secrets or response bodies. A quota rejection is not a generated output. A fallback retains the same lab run, model, inputs, prompt, settings and reserved slot; both attempts share a 540-second request budget. Every new run tries the primary first.

Unexpected output dimensions retain the exact rejected bytes privately for operator inspection, with actual dimensions, hash, usage and provider request ID. `options.diagnosticOutput` describes this artifact; `output` remains null and normal asset routes reject it. No resizing or acceptance is implied.

Each accepted run reserves one of the project's generation slots; the global lab also limits admission to 120 runs per rolling day. Provider calls run on the existing Studio queue. A write-first reservation serializes SQLite quota/idempotency decisions. A submitting checkpoint prevents accidental repeat charges. Known fal requests poll the same request ID; ambiguous submissions stop for operator review. Provider output is persisted privately before reporting completion. Accepted or ambiguous requests are never automatically resubmitted.

`iguide-lab:seed <project-id> <manifest.json>` imports a JSON array containing local `file`, `label`, `projection` and optional case fields. `iguide-lab:export <project-id> --output=<file>` exports provenance and run outcomes without credentials. Neither command publishes imagery.

Validation: `tests/Feature/IguideLabTest.php` covers capability expiry, resource/reference isolation, source metadata, strict projection, model/option allowlists, quota/idempotency, request settings, private outputs, ambiguous requests, and fal request reuse. Model capabilities are documented at https://developers.openai.com/api/reference/resources/images/methods/edit and https://fal.ai/models/bytedance/seedream/v5/pro/edit/api; successful real outputs remain an independent benchmark, not a unit-test claim.

## Derived panoramas and v2 controls

The index exposes `capabilities.schemaVersion: 5`, `composites: true`, `selectedObjectInstructions: true`, `maskUpload: true`, and `nativeCompositeUpload: operator_only`. A client must inspect supported features and minimum schema versions before enabling writes, rather than require an exact old schema version. The legacy `openaiComplexity` list remains for older 2.6 clients; new clients must use each exact model's `capabilities.complexity` supported/values/default fields.

`options.complexity` is honored in the exact 2.6 multipart request. An explicit complexity on 2.5 or Seedream is rejected. `options.declutterMode: selected-object` requires `selectedObjects` (up to 20 descriptions of 300 characters) and optionally `preserveObjects`. This recipe omits generic decluttering entirely. These are text instructions, not painted masks. Generic mode and medium complexity preserve the original recipe and idempotency hash; altered recipes record version 2. New 2.5 models and accepted composite references use recipe version 3.

`POST /api/iguide-lab/cases/{id}/composites` takes multipart `preview` (PNG, 2048 x 1024, at most 30 MiB) and `manifest` (JSON, at most 64 KiB). It returns 201 for creation, 200 for an identical request ID, or 409 for changed content. `GET /composites/{id}` and the index's `composites` array return the separate artifact DTO. Composites never dispatch model jobs or increment generation counters, and never claim a single provider/model/usage. Stored `completed` means the files were saved, not quality acceptance; `latestReview` starts null.

Required manifest fields: `schemaVersion:1`, `requestId`, `label`, `kind:locally_composited_panorama`, `projection:equirectangular`, `resolutionStrategy:preview_only|native_canvas`, `compositionMode:masked_whole_panorama|perspective_sections|hybrid`, `source:{caseId,sourceSha256,originalSha256,originalWidth,originalHeight}`, `preview:{sha256,width,height}`, `generatedDetail:{width,height,description}`, `recipeSha256`, and `children`. Optional fields are `native:{sha256,width,height}`, `geometryManifestSha256`, `scenePlanSha256`, `qaManifestSha256`, and bounded `lineage` operator evidence. Unknown top-level claims are rejected, including `accepted` and provider identity.

Each child contains `runId`, `requestId`, `outputSha256`, `projection`, `editScope:masked|entire_view`, optional `maskSha256`, and optional `view:{yaw,pitch,hFov,vFov,coordinateConvention}`. Children must be completed, belong to the same capability, and match exact stored bytes. Their source must be the parent case or name it in `metadata.parentCaseId`. Masked children require a mask fingerprint. Rectilinear children require view geometry and `geometryManifestSha256`. Generated-detail dimensions equal the maximum actual child output dimensions, independent of native canvas size. Geometry, masks, and metric hashes establish supplied lineage, not automatic verification of visual quality.

`php artisan iguide-lab:import-composite PROJECT CASE MANIFEST PREVIEW --native=NATIVE` is the private operator path for a native PNG (at most 128 MiB / 64 MP). Native canvas dimensions must equal the original scan metadata and its distinct fingerprint must already be recorded. A browser upload cannot claim a native canvas without its file. Neither preview nor native bytes are reencoded. Private asset routes are `/api/iguide-lab/assets/composite-preview/{id}` and `/api/iguide-lab/assets/composite-native/{id}`; the native response is an attachment. The DTO exposes `preview`, nullable `native`, `manifest`, `singleProviderOutput:false`, `resolutionStrategy`, and `latestReview`.

`POST /composites/{id}/reviews` uses the existing run review body and identical append-only acceptance/idempotency rules, in a separate artifact review table. Existing raw run reviews remain unchanged. All lab reads and writes use independent, explicitly named capability rate buckets (180 reads/minute, 30 writes/minute), so polling does not consume the write allowance.
`manifest.preset` is required and must match at least one child provider run; nullable `manifest.style` uses the five-style allowlist. The composite DTO exposes both fields explicitly.

## Reusable grass pipeline and accepted references

`capabilities.pipelines` is `{supported:true,automaticAcceptance:false,recipes:[{id,version,ready,preset,projection,supportsExistingRun,output,supportModelId}]}`. The sole recipe is `grass-masked-replacement`, version `grass-masked-replacement/1`, full panorama only, 2048x1024 preview output, with support model `fal-ai/sam-3-1/image`. Runtime readiness requires the private Python environment and fal configuration; it is independent from model readiness.

`POST /pipelines` accepts UUID `requestId`, `caseId`, the recipe, and either `existingRunId` or `modelId` plus optional `prompt` and `options.complexity`. Existing runs must be completed grass edits of this same case, 2048x1024, with a retained prepared-input fingerprint; they cannot receive new generation settings. New runs reserve an ordinary child run with its own stable request ID. Both paths then reserve exactly one SAM lawn segmentation. Pipeline admission is limited to 120 per project and 120 across all projects per rolling day. Existing image generation counters remain independent from segmentation reservations.

`GET /pipelines/{id}` and index `pipelines[]` expose request/child/support IDs, stage, known provider receipt, actual mask count, usage if supplied, nullable unknown cost, planned call counts, source PNG fingerprint, diagnostics, statistics, nullable compositeId/alphaAssetPath and safe error text. Stages are queued, editing, segmenting, compositing, completed, needs_attention or failed. `/assets/pipeline-alpha/{id}` serves the private applied alpha. A completed pipeline creates a separate **unreviewed** composite; no quality review is synthesized.

The queue uses write-first claim and receipt checkpoints. An ambiguous SAM POST is never repeated; a confirmed receipt can resume GET polling. Source pixels are reproduced using the same GD PNG preparation as the child request and must match its recorded SHA before SAM is submitted. The local numpy/Pillow compositor has no credentials or network calls; it performs periodic spherical feathering, preserves exact source pixels outside alpha, reports mask wrap diagnostics, and does not perform fixture-specific hole filling. Raw SAM masks, provider metadata and compositor report remain private for diagnosis. This mechanical proof does not establish semantic lawn boundaries or visual acceptance.

The pinned user-owned runtime path is configured by `iguide-lab.pipeline_python_path`; production uses Python3.12, numpy2.5.4 and Pillow13.0.0 in a private venv. No system Python modification is required. Five numerical tests in `tests/Python/test_iguide_grass_composite.py` cover longitude roll, poles, exact protected pixels, identity and invalid shapes/settings. Feature tests cover reservation replay, source binding, scoped assets, worker resume and unknown paid submissions.

`options.referenceCompositeIds` accepts accepted artifacts as reference images, with a maximum of three combined case/run/composite references. Reservation requires same-project completed records, a current accepted review and a matching preview SHA; these are rechecked before the paid request. Stored `referenceCompositeProvenance` preserves reservation review ID, preview SHA and reference role, plus the review ID used at submission. The original target remains first in the provider's image array. Empty composite-reference input preserves old request identity.

`POST /composites/{id}/display-metadata` accepts UUID requestId, label (160 characters), generatedDetailDescription (1000), and reason (1000). It appends a bounded display correction with identical-request replay, separate from QA reviews. DTO `displayMetadata` exposes the latest audited correction; original label, manifest, request hash, files and reviews remain unchanged. Clients may prefer this explicit display text while retaining the original manifest for provenance. No arbitrary metrics or acceptance overrides are allowed.

Pipeline `statistics` contains all five fields: `outsideAlphaMaxChannelDifference` (integer), `outsideAlphaPixels` (integer), `changedPixelFraction` (number), `maskPixelFraction` (number), and `wrapMaskDisagreementRows` (integer). Before composition it is null. A real numerical smoke fixture is `{outsideAlphaMaxChannelDifference:0,outsideAlphaPixels:1397176,changedPixelFraction:0.3337531089782715,maskPixelFraction:0.3337826728820801,wrapMaskDisagreementRows:103}`. This fixture proves neither semantic quality nor a paid pipeline execution. Support status can be pending, submitting, processing, completed or failed; pipeline completion never implies an accepted quality review.

## Source analysis and explicit draft application

`capabilities.sceneAnalysis` reports supported/ready, modelId `gpt-6-astra`, protocolVersion `scene-plan-v1`, automaticGeneration false, applyDraft true, maxAnalyses120/usedAnalyses, suggestedSectionMaxHfov120 and sectionExecution false. No section editing or arbitrary mask upload is implied.

`POST /analyses` takes UUID requestId, caseId, preset, nullable style, optional instructions (2500 characters), and strict options: roomType, furnitureDensity, lightingIntensity, preserveArchitecture, preserveFixedFinishes, allowFinishChanges, declutterMode, selectedObjects and preserveObjects. Selected-object mode requires declutter and explicit targets; lists allow eight entries of100 characters each. Combined instructions/serialized controls must fit4000 characters. Unknown top-level or nested controls are rejected. Default staging/interior style is modern. Other styles use the existing five-style allowlist.

Analysis reserves a separate idempotent record and a120-per-project/rolling-global-day technical safety ceiling; it never decrements image allowance or triggers image generation. The source SHA, exact semantic settings, protocol and view recipe bind the request. Images are the same source prepared to2K plus six1024-square cardinal/pole views at100-degree HFOV; rectilinear inputs use the source only. The fixed private Python adapter runs without credentials, limits address space to1536MiB and timeout to90seconds, and records exact source/view/implementation hashes and raw-image coordinate conventions. Cached views must retain their exact per-ID yaw/pitch, FOV, dimensions and decoded PNG contents. These are views of one capture, not additional cameras or verified3D geometry.

The Studio worker checkpoints submitting before one Responses request with store:false, no tools and a strict schema. The existing lab-primary/explicit-quota-only fallback policy applies unchanged. Ambiguous submissions never automatically replay. Incomplete/refused/schema-invalid results retain raw response and usage privately and stop for review. DTOs never expose raw response or reasoning; only compact grounded proposals and safe provider-attempt metadata are returned. Actual usage is retained, while estimatedCostUsd and pricingVersion are null because this release has no verified Astra price.

`GET /analyses/{id}` and index analyses[] return status queued/preparing/submitting/completed/failed/needs_attention; source/original/prepared hashes; normalized settings; protocol/model/provider IDs; private diagnostic view metadata/paths; nullable proposal/proposalSha256; usage; timing and safe error. `/analyses/{id}/views/{source|front|right|back|left|zenith|nadir}` serves scoped private diagnostic PNGs. Proposals expose summary, protectedFeatures, targets, sourceArtifacts, uncertainties, suggested workflow/sections, generationPrompt and required reviewChecks. They always remain unreviewed with geometryVerified/maskVerified/crossViewVerified/automaticGeneration false. Framing requiring more than120-degree HFOV is explicitly uncertain/manual review, never silently clamped.

Apply proposed draft is an explicit local UI action and makes no image request. On a later explicit Generate, pass the edited draft in prompt and options `{analysisId,promptMode:scene-plan}`. The server requires the same completed analysis/project/case/source/preset/style and semantic edit controls, then uses that exact standalone draft without generic preset boilerplate. It records proposal/source/prepared/draft hashes and whether the user edited the proposed text. Image model and supported sampler complexity remain selectable for comparisons. Changing source/edit controls requires a new analysis or detaching the association; detaching removes analysisId and restores promptMode preset. Default/absent analysis fields preserve old request hashes. Before provider submission the actual source bytes and prepared PNG must still match the applied analysis. Suggested sections are advice only, and no automatic section execution or acceptance occurs.


## Reviewed support and native section editing

Schema5 exposes `capabilities.sectionEditing`: runtime readiness, fixed2048-square cut size, user-selected HFOV30-130, source-hash attachment requirement, exact2.6 provider-mask model IDs, white-edit/black-preserve mask convention and0.1 section edge inset. Scene-analysis `sectionExecution:false` still means suggestions are not executed automatically; explicit section controls are separate.

`POST /cases/{id}/native-source` takes multipart image/requestId. Its actual upload hash and dimensions must match the parent case original provenance. It creates an immutable native-source helper and stores a server-owned `case.nativeSource` snapshot (caseId/requestId/sha256/width/height). The parent preview bytes remain unchanged. Exact replay returns the same helper with201; another requestId after attachment returns409. Clients recover the saved attachment on reload. An unknown original can instead be uploaded as a new ordinary case. Native uploads retain the30MiB/64MP limit. ICC profiles, nontrivial EXIF orientation, animation and transparent source pixels require an explicit normalized source with a new hash; the adapter does not silently transform them.

`POST /sections` accepts requestId, actual native caseId and view:{yaw,pitch,hFov}. Bounds are yaw[-180,180], pitch[-90,90], HFOV[30,130]. It reserves a local Studio job and returns202. `GET /sections/{id}` and index sections[] expose queued/extracting/completed/needs_attention, source hash, nullable source dimensions, exact view plus2048-square dimensions, nullable geometry/cut hashes and private cutAssetPath/derivedCaseId, error and timestamps. Before completion those derived fields are null. The derived rectilinear helper explicitly enables Generate/Analyze in the section workflow. Its metadata names the native parent; the native helper in turn names the visible preview parent. Clients group results under that visible parent while retaining the actual native case identity in provenance.

`POST /sections/{id}/masks` or `/pipelines/{id}/masks` accepts requestId, reviewed:true and an opaque8-bit grayscale/equal-RGB PNG (max8MiB). White255 means replace/edit, black0 means preserve, and gray values retain exact local feather coverage. User review confirms support only, never output acceptance. Section masks are2048-square, and every nonzero value must be inside the outer10-percent border to avoid geometric edge taper; reposition or widen the cut otherwise. Grass revision masks are2048x1024. Normalized support and uploaded hashes remain separate. `/masks/{id}/asset` is capability-scoped. New mask returns201, identical replay200. No semantic segmentation is invoked.

For a later explicit image generation, existing `/runs` accepts options.sectionId and optional sectionMaskId, caseId=section.derivedCaseId. Source/native/cut/geometry/mask identity is checked before paid reservation and again by the worker. Only the exact2.6 Sunburst/Flare models accept provider masks. Their multipart request contains clean image[] parts plus a distinct mask PNG with alpha=255-support; the mask is never an image reference. Provider mask behavior is soft guidance, not a hard pixel guarantee. Existing unmasked recipe hashes remain unchanged; section operations use recipe5. A full-panorama analysis is not silently applied to a different section source.

`POST /sections/{id}/compositions` or `/pipelines/{id}/compositions` takes requestId, completed runId and reviewed maskId. It queues only local pixel work and returns202; `/compositions/{id}` and index compositions[] expose queued/compositing/completed/needs_attention, child/mask IDs, nullable compositeId/alphaAssetPath/alphaSha256/statistics, providerCalls:0, automaticAcceptance:false and timestamps. Section composition requires the same immutable native source for extraction and output canvas. Grass revision reuses the existing pipeline source and candidate, preserves supplied gray alpha exactly, and does not call SAM or an image provider. `/compositions/{id}/alpha` serves the actual applied panorama support.

Native geometry runs one job at a time using a shared database lock, a fixed Python argv, stripped environment,240-second subprocess timeout and3GiB address-space cap. Each result is atomically committed with request/code/source/output/mask fingerprints. A native image is exported only when the uploaded source itself is larger than2K. Every result also includes a2K browser preview and a separate unreviewed composite record. Native canvas size does not restore detail lost to2048-square generation. Zero changed decoded source pixels outside actual alpha is checked before the artifact is stored; this is a mechanical preservation proof, not semantic, seam or cross-view acceptance. No review is inherited from an earlier artifact.

Validation covers scoped source/mask assets, native attachment/replay, extraction recovery without duplicate helper cases, separate provider multipart mask fields, pre-admission binding, changed-source rejection, local-only composition, exact alpha bytes and failed-proof storage. The private pinned Linux runtime was measured on a11008x5504 original: extraction2.79s/846MiB peakRSS, native composition23.11s/854MiB, exact replay0.997s. These are one fixture's measurements, not latency guarantees or accepted output quality.

## Optional local boundary harmonization

`capabilities.sectionEditing.harmonization` separately reports `supported`, `ready`, `modes:[exact-domain-harmonic-v1]`, `sectionOnly:true`, `automaticAcceptance:false`, and limits `{maxEditablePixels:131072,maxClippedPixelFraction:0.05,maxOvershoot:64}`. The client must opt in explicitly. The existing section composition request accepts optional `harmonization:exact-domain-harmonic-v1`; missing or `none` retains the original V5 identity and ordinary replacement. Changing the mode under the same request ID returns 409. Grass pipeline recomposition rejects this mode. No image-generation options or provider calls are added.

The optional pre-step solves a four-neighbor Dirichlet correction on positive support pixels, using source-minus-candidate values only at the domain exterior. It preserves candidate gradients without putting the removed original object back into the selected interior. It does not expand or feather support. The corrected RGB remains unassociated; the unchanged gray support is applied exactly once by the existing native compositor. Raw provider bytes and previous compositions remain immutable. Artifact children retain the real provider output hash, while `manifest.lineage.harmonization` records the separate local correction.

Reservation snapshots the exact source-cut, solver, adapter and validated runtime manifest hashes. Both readiness and the worker require the manifest's validated code hashes to equal the current files, then recheck inputs before execution. A separate user-owned Python 3.12.3 / NumPy 2.5.4 / Pillow 13.0.0 / SciPy 1.18.1 runtime is configured by `harmonization_python_path` and `harmonization_runtime_manifest`; the existing native geometry runtime is unchanged. SciPy exits before native arrays are loaded. BLAS uses one thread; the pre-step has a 1,536 MiB address-space limit, 55-second CPU limit and 65-second wall timeout.

The solver rejects more than 131,072 editable pixels, nonfinite values, excessive residual, sparse factor storage above 128 MiB, more than 5% clipped editable pixels, or maximum channel overshoot above 64. Clipping bounds are conservative experimental operational limits, not calibrated quality approval. Successful output remains Unreviewed. The DTO's nullable `harmonization` field contains captured recipe hashes, limits, status, nullable corrected-candidate/clipping hashes, nullable `clippingMaskAssetPath`, diagnostics and error code. Rejected clipping maps remain privately available through `/compositions/{id}/harmonization-clipping`; white means a channel clipped, not edit support. Diagnostics can be null or a smaller rejection object after a preflight/process failure. Clients must preserve the rich bounded telemetry without assuming a closed subset of success fields.

Linux validation covers 21 solver/adapter tests and fresh-process kitchen plus 131,072-pixel compact, disconnected and near-square cases. Observed peaks were about 211-312 MB, with 92-284 ms solver time. The real kitchen result matched the reviewed decoded pixels exactly, while PNG encoding differed across Pillow builds. CLI replay retained identical output/report identity, and actual PHP-FPM UID 33 could read the private manifest, report and diagnostic files. These bounded fixture results establish mechanics and resource headroom, not universal quality or performance.

## Bounded source capacity and stored output identity

Projects default to 80 source records, counting preview uploads, native attachments and derived sections. An operator may set one active project to an integer limit from 80 through 160 with `php artisan iguide-lab:set-case-limit PROJECT_UUID 160`. There is no public quota-write endpoint. The command refuses a reduction below the existing record count; token, expiry and all paid quotas remain unchanged. Every source admission obtains the project write lock before its final count check. Exact upload/native/section recovery remains available at capacity. Section recovery uses the complete section ID and native parent, so equal pixels and a colliding short display label cannot attach a different section's helper.

Completed run `output.sha256` is nullable. New jobs persist the digest of the final encoded PNG stored privately, independently of provider/request metadata. Historical rows stay null until the operator runs `php artisan iguide-lab:verify-output-digests PROJECT_UUID`. The command verifies at most 120 completed outputs for that project, each at most 32 MiB and 4,624,220 pixels. It requires an owned PNG path and matching recorded dimensions; missing, corrupt, foreign, symlinked or changed-digest outputs stop the operation. It never replaces an existing digest. Reading/decoding and the first hash occur outside the database write lock; the short write transaction rechecks the record binding, file identity and final byte hash before persisting. Previously verified rows may remain committed if a later row fails. Replaying the command verifies the same stored bytes without changing request identity, image data, quality review or paid allowance.

Index/record DTO reads use only the authoritative stored digest and never hash image files. Imported receipt assertions and client-supplied hashes are not trusted digest sources. Null legacy digests remain safe for clients that require a verified child hash before navigating imported camera focus. Rollback removes only the new capacity/digest columns and retains image records and bytes; projects then use the original 80-record admission ceiling without deleting existing sources.
